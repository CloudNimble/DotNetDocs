# Mintlify.Core Schema Gap Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `Mintlify.Core` back in line with the live Mintlify `docs.json` schema so load, validate, merge, and save round-trip every documented property.

**Architecture:** Keep the existing flattening converters (`string` → `IconConfig`, `string` → `ApiSpecConfig`) and the current inheritance tree (`NavigationItemBase` → `NavigationContainerBase` → `NavigationSectionBase`). Add missing properties and models; extend converters only where JSON token shape changed. Do not introduce C# 15 union types in this pass — `Mintlify.Core` still targets `netstandard2.0` through `net11.0`.

**Tech Stack:** C# 15, System.Text.Json (source-generated on net8+ via `MintlifyJsonContext`), MSTest v3, FluentAssertions, Breakdance.

**Schema snapshot:** 2026-11-01 from [https://www.mintlify.com/docs.json](https://www.mintlify.com/docs.json) (same document as [https://leaves.mintlify.com/schema/docs.json](https://leaves.mintlify.com/schema/docs.json)). Checked in at `src/Mintlify.Core/Schemas/docs.schema.2026-11-01.json` (pretty-printed, excluded from the nupkg). Name later snapshots `docs.schema.YYYY-MM-DD.json`.

**Branch:** `feature/mintlify-updates-nov-2026` off `origin/dev`.

## Lessons learned

Record these before touching remaining tasks. They cost real debugging time.

### `NavigationJsonConverter` is a hand-written allow-list

`NavigationConfig` does **not** use default STJ property discovery. `NavigationJsonConverter` reads and writes named properties only. Adding `Graphql` / `Mcp` to the model was not enough: generated `docs.json` dropped them until the converter grew `graphql` and `mcp` (and, while there, `dropdowns` / `languages` / `versions` / `global` on **read** — those were already written but skipped on load).

Any new property on `NavigationConfig` (`sdk`, `directory`, `searchable`) **must** be added to both `Read` and `Write` in that converter.

Tab/Group/Anchor inherit `NavigationItemBase` and use normal serialization, so properties there round-trip without this converter.

### Do not register `List<string>` converters globally

`MarkdownInstructionsConverter` on `MintlifyConstants.JsonSerializerOptions.Converters` recurses forever because every `List<string>` in the graph hits it. Keep it on `MarkdownConfig.Instructions` only, and deserialize arrays with options that omit this converter (same pattern as `ApiConfigConverter`).

### `?.` after `IsNullOrWhiteSpace` does not satisfy CS8602

`if (string.IsNullOrWhiteSpace(config.Banner?.Type)) return; config.Banner.Type` still warns. Bind `var bannerType = config.Banner?.Type` first. Same for `Mixpanel?.Region`.

### Merge is a second allow-list

`DocsJsonManager.Merge` copies named root properties, then `MergeNavigation` / `MergeGroupConfig` / `MergeTabConfig` copy named nav fields. New root objects disappear in collection builds unless added to Merge. New nav fields (`Graphql`, `Mcp`, later `Sdk`) disappear unless added to the group/tab merge helpers.

Parser coverage is a third allow-list: `ParseSpecRefConfig` must be called from every nav-node parser (`ParseTabConfig`, `ParseGroupConfig`, `ParseAnchorConfig`, `ParseDropdownConfig`, `ParseProductConfig`). MenuConfig still has no GraphQL/MCP on the object model.

### Tests belong on `DocsJsonManagerTests`, not dumpster round-trip classes

Isolated `JsonSerializer.Serialize(new Foo { ... })` tests were the wrong shape. Config-shape coverage is `DocsJsonManagerTests.<Type>.cs` partials that `Load` a real `docs.json` fragment and `Save`/`Load` again. Converter-only polymorphism (string vs object) stays in `Converters/*ConverterTests.cs`.

`NewConfigTests` and `SchemaGap2026Tests` were deleted. `DocsJsonManagerTests` is a partial split by **operation** (`Merge`, `PopulateNavigation`, `ApplyUrlPrefix`) and by **config shape** (`Markdown`, `Seo`, `Banner`, …).

`dotnet test` on this repo’s SDK 11 MTP projects is `dotnet exec path/to/Test.dll`, not `dotnet test --filter` (VSTest target is rejected).

### Extra additive property found during docs pull

`packages` was not on the first gap list. It is a root object that enables third-party npm libraries in MDX. Keep it. See https://www.mintlify.com/docs/customize/third-party-libraries.

Themes `sequoia` and `luma` were also missing from `ValidThemes` / `MintlifyOptions`.

### C# 15 unions do not unlock this pass

Unions would model string-or-object fields honestly on net11, but `Mintlify.Core` multi-targets `netstandard2.0` through `net11.0`. Flattening converters stay. STJ still needs classifiers for object-vs-object cases (navigation pages, Shiki codeblocks).

### XML cref to inherited members fails CS1574

`see cref="TabConfig.Pages"` does not resolve; Pages lives on `NavigationItemBase`. Use the declaring type. `TreatWarningsAsErrors` turns this into a build break.

## Global Constraints

- Always specify `--configuration Release` on `dotnet` commands.
- Follow `.editorconfig` and `Agents.md` / `Claude.md`: 4-space indent, newline before braces, block-scoped namespaces, `#region` order Fields / Properties / Constructors / Public Methods / Private Methods, public-then-protected-then-internal-then-private, alphabetical within groups.
- Extensive XML docs on public APIs; `<param>` on the same line as content; `<remarks>` last; include `<example>` / `<code>` where the schema has a concrete JSON shape.
- Prefer `ArgumentException.ThrowIfNullOrWhiteSpace()` / `ArgumentNullException.ThrowIfNull()` only in net8+ code paths; `Mintlify.Core` still has a `netstandard2.0` TFM.
- Prefer `.IsNullOrWhiteSpace()` over `.IsNullOrEmpty()`.
- Tests live in `Mintlify.Tests.Core` as `DocsJsonManagerTests` partials (Load/Save) or converter tests. MSTest v3, FluentAssertions, no mocks, no Arrange/Act/Assert comments, `.NotBeNullOrWhiteSpace()` for strings.
- Register new independently-serialized types on `MintlifyJsonContext` only if they are deserialized as roots; property types are discovered automatically.
- Do not change `global.json`.
- Do not drop TFMs. Do not introduce `union` types in this pass.
- Preserve existing public property names and flattening behavior unless a task explicitly calls for a converter change.
- `DocsJsonManager.Merge` now copies all current root chrome when `combineBaseProperties` is true. **New** root properties and **new** nav fields still must be added to Merge / `MergeGroupConfig` / `MergeTabConfig` / `NavigationJsonConverter` in the same task that adds them.

## Review Focus

- A real `docs.json` that uses `api.params.expanded: "closed"` (string enum) must load; the current `bool?` property will throw today.
- A navigation `pages` array that contains `{ "type": "link", "href": "...", "title": "..." }` must load; `NavigationPageConverter` throws today.
- `api.openapi` as an array of objects with `overlays` must load; `ApiConfigConverter` currently treats arrays as `List<string>`.
- Round-trip JSON must omit nulls and keep camelCase (`MintlifyConstants.JsonSerializerOptions`).
- Merge of two configs must keep newly added root properties from the source when they are non-null.
- Adding a property to `NavigationConfig` without updating `NavigationJsonConverter` will silently drop it.

### Task 3: Navigation page polymorphism

**Effort:** L.
**Status:** Done.

**Files:**
- Create: `src/Mintlify.Core/Models/NavigationLinkConfig.cs`
- Create: `src/Mintlify.Core/Models/SourceRefConfig.cs`
- Modify: `src/Mintlify.Core/Converters/NavigationPageConverter.cs`
- Modify: `src/Mintlify.Core/Converters/NavigationPageListConverter.cs`
- Test: `src/Mintlify.Tests.Core/Converters/NavigationPageConverterTests.cs`

**Schema:** a `pages` item may be:

1. `string` — page path (existing).
2. object with `group` — `GroupConfig` (existing).
3. `{ "type": "link", "href": string, "title": string }` — external/nav link.
4. `{ "sourceRef": string }` — inline a git-source navigation section.

**Read algorithm:** `StartObject` → buffer the JSON object, inspect keys:

- has `"group"` → `GroupConfig`
- has `"sourceRef"` and no `"group"` → `SourceRefConfig`
- has `"type"` equal to `"link"` (ordinal ignore case) → `NavigationLinkConfig`
- else → `GroupConfig` for backward compatibility, or throw with the property names found

**Write:** `string`, `GroupConfig`, `NavigationLinkConfig`, `SourceRefConfig`. Keep throwing on unknown CLR types.

Merge keeps unknown page types via the `default` arm (links and sourceRefs are added, not treated as duplicate paths). `CollectPagePaths` / `ApplyUrlPrefixToPages` only walk strings and groups, so external hrefs are not prefixed.

- [x] `NavigationLinkConfig` / `SourceRefConfig`
- [x] `NavigationPageConverter` dispatches on `group` / `sourceRef` / `type=link`
- [x] Load/Save mixed pages array
- [x] SDK: `<Page>`, `<Link Href Title>`, `<SourceRef>`, `Page Type="link"`
- [x] `docsproj.mdx` notes link and sourceRef page entries
